# SigMA Copilot MVP 售前试用指南

> **版本：** MVP 功能验证版
> **适用对象：** 售前工程师、演示人员
> **编制日期：** 2025-07

---

## 一、产品简介

**SigMA Copilot** 是一个面向 NVH 测试数据分析的对话式 AI 助手。用户可以用自然语言描述想查看的数据范围和分析需求，Copilot 自动理解意图、构建筛选条件、查询记录、并执行数据分析或导出任务。

**核心价值一句话：** "说话即查数"——不用记查询界面、不用填表单，用日常语言就能完成记录检索、数据导出和指标观察。

| 项目 | 说明 |
|------|------|
| 适用角色 | NVH 测试工程师、数据分析师、产品验证人员 |
| 当前阶段 | MVP 功能验证版，用于现场演示与需求收集 |
| 核心能力 | 自然语言记录检索、多轮筛选、Excel/TDMS 导出、趋势/频谱观察 |

## 二、快速开始

### 前置依赖

| 依赖 | 说明 |
|------|------|
| Python ≥ 3.12 | 运行环境 |
| LLM 服务 | OpenAI-compatible endpoint，默认 `http://localhost:1234/v1`，模型 `qwen/qwen3-4b-2507` |
| SigMA 后端 | 默认 `http://192.168.0.65:8081`，需有效 token |
| 操作系统 | Windows / Linux / macOS 均可 |

### 启动步骤

```powershell
# 1. 安装依赖
cd sigma-copilot-mars
pip install -e ../themis
pip install -e .

# 2. 设置环境变量（按实际环境修改）
set SIGMA_TOKEN=<你的Sigma后端token>
set SIGMA_BASE_URL=http://192.168.0.65:8081    # 如果不同

# 3. 启动 LLM 服务（示例：LM Studio / Ollama / vLLM）
# 确保 localhost:1234 上有 qwen/qwen3-4b-2507 模型在运行

# 4. 启动演示
cd demo-chat
python run.py --port 8000
```

浏览器打开 `http://localhost:8000` 即可进入对话界面。

### 首次启动注意

**embedding 模型（Qwen3-Embedding-0.6B）第一次加载需要 30 秒到 2 分钟**，取决于网络和机器性能。这段时间内意图识别会降级。建议启动后先发一条"你好"暖机。

## 三、功能演示清单

以下按演示推荐的顺序排列，每个功能给出"推荐话术 → 预期响应"，方便现场逐个走。

### 3.1 简单记录检索（必演，最稳）

| 推荐话术 | 预期行为 |
|----------|---------|
| "查看最近一周不合格的记录" | 返回记录列表，显示记录数、型号、测试时间等 |
| "只看 A 型号的数据" | 在当前筛选结果上叠加型号筛选 |
| "只看最近的 50 条" | 限制返回数量为 50 条 |
| "只看传感器 Vib1 的数据" | 叠加传感器筛选 |

**演示要点：** 这是 MVP 最稳定的路径。先查询再用自然语言逐步叠加筛选条件，展示"多轮对话"能力。

### 3.2 时间范围表达（重点秀）

| 推荐话术 | 覆盖的能力 |
|----------|------------|
| "今天的数据" | 单日相对时间 |
| "最近一周" | 滚动窗口 |
| "本周"、"本月" | 日历周期 |
| "6 月 11 日到 6 月 22 日" | 起止范围 |
| "今年上半年" | 半年表达 |
| "6 月以来" | 从某时至今 |

**演示要点：** 展示中文时间表达的自然理解能力，这是用户对 AI 能力感知最强的部分。

### 3.3 综合结果筛选

| 推荐话术 | 预期行为 |
|----------|---------|
| "只看不合格的" | 过滤 summary_result=不合格 |
| "只看 NG 的" | 别名解析，等同于不合格 |
| "只看合格的" | 过滤 summary_result=合格 |

**演示要点：** 系统内置了常用别名映射（NG→不合格，OK→合格）。

### 3.4 Excel 导出（如果后端有数据）

| 推荐话术 | 预期行为 |
|----------|---------|
| "导出这些记录的 Excel" | 进入导出准备流程，会询问传感器选择和数据类型 |
| "导出 Vib1 的一维数据到 Excel" | 直接指定传感器和数据类型 |

**注意：** 导出依赖 selection 结果非空 + SigMA 后端可用。如果后端没有对应数据，会返回错误提示。

### 3.5 数据观察（查看指标图表）

| 推荐话术 | 预期 |
|----------|------|
| "查看这些记录的 RMS 趋势" | 展示趋势图 |
| "查看频谱"、"查看阶次谱" | 展示对应分析图表 |

**注意：** 数据观察依赖 SigmaDataObservationCatalogClient 连得上 SigMA 后端。

### 3.6 Origin 原始数据导出

| 推荐话术 | 预期 |
|----------|------|
| "导出这些记录的原始数据" | 进入导出确认流程 |

**注意：** 默认导出格式为 TDMS，会先确认 selection 范围再执行。

### 3.7 不支持的意图（展示边界）

| 推荐话术 | 预期行为 |
|----------|---------|
| "你好" | 回复能力介绍或不支持的业务操作 |
| "帮我写一段代码" | 回复不支持 |

**演示要点：** 展示系统能识别自己不会什么，比假装会但给出错误结果好。

## 四、对话技巧（给演示者）

1. **一次说一件事。** 虽然系统能处理复合意图（如"去掉 Vib1 加上 Vib2"），但演示时分开说更容易控制节奏。
2. **先查再看。** 推荐演示路径：先说时间/型号/结果筛选查记录 → 再在结果上做观察或导出。这会展示"多轮对话"的价值。
3. **等待响应完成。** LLM 推理需要 2-5 秒，加载 embedding 模型的首轮需要 10-30 秒。不要在响应返回前连续发消息。
4. **如果意图识别错误，重新措辞。** 同样的意思换一种说法往往能命中。例如"查数据"不行就试"查看最近一周的记录"。
5. **MVP 不支持随时回退到上一个筛选结果。** 演示中不要期待"撤销上一步"。
6. **如果先导出了数据，当前选中不会丢失。** 可以展示"同一批数据先查、再导出、再看趋势"。

## 五、已知限制与注意事项（完整版）

### 5.1 架构与基础设施

| 限制 | 详情 | 影响 | 现场应对 |
|------|------|------|---------|
| **全内存会话** | `ConversationStateRepository` 是 dict 实现，`InMemorySelectionSetRepository` 同理 | 进程重启、崩溃、OOM 都会丢失所有上下文。演示中不能"关了重开继续聊" | 演示前重启服务，全程不要重启；演示机保证内存充足 |
| **单实例无锁** | 会话状态没有并发控制，同一 session_id 并发请求直接竞态 | 多窗口同时操作同一会话会导致 selection 状态错乱 | 一个 session_id 只用一个浏览器标签页 |
| **LLM 单点依赖** | 识别链路完全依赖外部 LLM，没有 fallback 到规则引擎或本地模型 | LLM 服务挂了整个 `/turns` 不可用 | 演示前 ping 一下 LLM 服务；准备一个备用端口 |
| **LLM 无超时保护** | LLM 调用没有用户可感知的超时，卡住就是前端一直转圈 | 用户体验差，且不知道是否该重试 | 如果 30 秒没返回，果断刷新页面重发 |
| **Embedding 模型冷启动** | 首次请求触发 `sentence-transformers` 下载/加载 Qwen3-Embedding-0.6B，约 500MB | 首轮延迟 30 秒 ~ 2 分钟，期间 Themis 降级 | 启动后用废话（"你好"）暖机；如果机器允许，把 `build_index_on_init` 改为 `true` |
| **没有健康检查端点** | `/turns` 是唯一的业务端点，没有 `/health` | 不知道服务是否真的就绪 | 启动后访问 `http://localhost:8000/chat`，页面能打开 + LLM 服务正常 = 就绪 |
| **没有请求日志** | 没有结构化请求日志或 tracing | 演示中问题难排查 | 启动 uvicorn 时加 `--log-level debug` 能看到一些信息 |

### 5.2 识别与意图理解

| 限制 | 详情 | 现场应对 |
|------|------|---------|
| **仅 NVH 领域** | 意图 YAML 全是 `nvh.*` 域。问"帮我分析发动机振动"之外的任何事都会进 `low` 或 `unsupported` | 不要尝试让系统做通用问答、写代码、翻译 |
| **不支持混合域** | 无法在一次请求里同时做"查 NVH 记录"和"问天气" | — |
| **模糊指代不可靠** | "上面这些"、"刚才那个"、"这批数据"等回指依赖 `recent_selection_ids`，但引用解析逻辑很薄 | 每轮都显式说型号/时间/条件；不要用代词 |
| **中文为主，英文有限** | 意图的 `embed_text` 和 `tree_text` 绝大多数是中文 | 演示用中文 |
| **同义词覆盖不完整** | Resolver 别名映射是硬编码的，不会动态学习用户说法 | 如果说了别名没命中，换官方术语（说"不合格"而不是"挂掉了"） |
| **LLM 输出非确定性** | `temperature=0.1` 很低但不是 0，相同输入偶尔会有不同输出 | 识别异常时换个说法重试，不要纠结"为什么上次可以" |
| **复合意图有上限** | "去掉 Vib1 加上 Vib2"OK，但三层以上嵌套可能不稳定 | 拆成两三轮说 |
| **不支持否定排除** | "除了 A 型号之外的"、"不要 Vib1"这类排除语义路径不完整 | 用正向筛选代替排除 |

### 5.3 时间范围

| 限制 | 详情 | 现场应对 |
|------|------|---------|
| **确定性解析优先，但不全** | 覆盖了常见中文表达但"上上周"、"下周"、"未来一周"等不在覆盖列表中 | 尽量用指南中列出的已验证表达 |
| **LLM 时间抽取有失败率** | 确定性解析失败后才走 LLM 抽取，LLM 返回 `AMBIGUOUS`/`LOW_CONFIDENCE` 时会进入澄清流程 | 澄清时手动选时间，或换一个简单的时间说法 |
| **相对时间锚点是服务端当前时间** | "最近一周"以服务器时间为准，不是客户端 | 确认服务器时间正确 |
| **不支持纯"年份"** | "2025 年的数据"不在覆盖范围 | 用"2025 年 1 月到 12 月"替代 |
| **时区硬编码为本地时区** | 没有时区配置，跨时区部署时"今天"可能偏移 | 演示环境保持服务器时区和用户时区一致 |

### 5.4 筛选与 Selection

| 限制 | 详情 | 现场应对 |
|------|------|---------|
| **筛选条件叠加不可撤销** | 没有 "undo"、"回退到上一个筛选" | 每一步筛选都确认好再说，错了只能重开会话 |
| **跨 Session 不可复用 SelectionSet** | 换 session_id 后所有 selection 从零开始 | 一次演示用一个 session_id |
| **SelectionSet 无过期机制** | 创建的 SelectionSet 永不过期（但重启丢失），没有自动清理 | 演示时间不长的话问题不大 |
| **产品配置变化不同步** | Resolver 候选值在会话开始时加载一次，中途 SigMA 后端新增配置不会被感知 | 演示中新加的配置不会出现在候选列表里，重启服务即可 |
| **模糊序列号匹配不支持** | "编号包含 1001"、"SN10*" 这类通配/模糊匹配不支持 | 用精确序列号 |
| **筛选条件不一定全量推送至 SigMA** | 如果新增了 filter 类型但 mapper 未更新，会静默丢失条件 | 演示时只用已验证的筛选维度 |
| **复合筛选的 AND/OR 逻辑有限** | 复杂嵌套（AnyOf 套 AllOf 套 Not）可能超时或 OOM | 简单的 AND/OR OK，不要故意测试极端嵌套 |

### 5.5 导出与任务

| 限制 | 详情 | 现场应对 |
|------|------|---------|
| **导出依赖 selection 非空** | 空 selection 时会走澄清流程要求先筛选数据 | 先查记录确认有数据，再导出 |
| **Excel 导出需指定传感器** | 进入导出流程后会列出可选 sensor 并要求用户选择 | 演示话术里直接指定传感器（"导出 Vib1 的 Excel"）可以跳过询问 |
| **Origin 导出格式固定为 TDMS** | 不支持在对话中切换导出格式 | 如果后端支持其他格式，需要改配置/代码 |
| **导出是同步等待** | 大文件导出可能超时 | 数据量大时（>千条记录）导出可能很慢，提前准备小数据量演示 |
| **没有导出进度反馈** | 提交后只能等结果，没有中间进度 | 同上 |
| **导出失败没有重试机制** | SigMA 返回错误后直接展示错误信息 | 查看错误信息后手动重试 |
| **没有下载链接持久化** | 导出结果中的文件链接/路径不保存到会话历史 | 导出成功后当场打开确认 |

### 5.6 数据观察

| 限制 | 详情 | 现场应对 |
|------|------|---------|
| **依赖 DataObservationCatalogClient** | 指标列表、数据域定义来自 SigMA 的 `/data-observation/catalog` 接口 | 提前确认该接口可用 |
| **指标名硬编码映射** | "看趋势"、"看频谱"等通过关键词/规则驱动，不是 LLM 理解 | 用指南里列出的术语：趋势、频谱、阶次谱、阶次切片、倒谱、心理声学 |
| **不支持"对比两个型号的趋势"** | 一次只能看一个 selection 范围的观察结果 | — |
| **数据观察结果不缓存** | 重复请求会重新查询 SigMA | 如果后端慢，观察可能也慢 |

### 5.7 前端与交互

| 限制 | 详情 | 现场应对 |
|------|------|---------|
| **demo-chat 是极简 UI** | 单页 HTML，没有加载动画、错误重试按钮、历史会话列表 | 演示风格就是"极简对话"，不要把它当产品 UI 卖 |
| **不支持 Markdown 渲染** | 富文本/表格/图表全靠前端自己渲染 | 如果后端返回了 Markdown，前端可能原样显示 |
| **提示词回复机制脆弱** | PromptReply 用 `prompt_id` 匹配，多发或少发都可能导致状态异常 | 按系统提示操作，不要跳过询问直接说下一步 |

### 5.8 安全与权限

| 限制 | 详情 |
|------|------|
| **无用户认证** | `/turns` 不校验用户身份，`session_id` 谁都可以伪造 |
| **无权限控制** | 不区分谁能查/谁能删/谁能导出 |
| **CORS 全开** | `allow_origins=["*"]`，任何来源都可以调用 |
| **token 明文传输** | `SIGMA_TOKEN` 从环境变量读取，如果通过 HTTP 传给前端或被日志打到可能有泄露风险 |
| **无审计日志** | 所有操作（包括导出、删除）没有操作记录 |

### 5.9 稳定性

| 限制 | 详情 |
|------|------|
| **无降级策略** | LLM 不可用时没有备用方案（如纯规则匹配） |
| **无熔断** | SigMA 后端慢或挂了，请求会一直等 |
| **无限流** | 没有 per-session 或 per-IP 限流 |
| **长 session 内存泄漏风险** | 每次 save 都往 dict 里写，没有 LRU 淘汰 |
| **异常处理偏粗** | 部分地方直接 `except Exception` 或返回空响应，不会给出有用错误信息 |

> **演示策略：** 重点演示"记录查询 + 叠加筛选 + Excel 导出/趋势查看"这条已验证的闭环。其余功能明确标注为"规划中"。

## 六、常见问题排查（FAQ）

| 现象 | 可能原因 | 处理方式 |
|------|---------|---------|
| 发消息后一直转圈 | LLM 服务未启动 | 检查 `localhost:1234` 是否可达 |
| 返回 "Turn handler is not configured" (503) | `SIGMA_ENABLE_MAIA=0` 或 runtime 构建失败 | 检查环境变量和日志 |
| 识别结果总是 "unclear" 或 "unsupported" | embedding 模型未加载完成 | 等 1-2 分钟再试 |
| 记录查询返回空 | SigMA 后端没有对应时间范围的数据 | 换一个时间范围或确认后端数据 |
| 导出失败 | SigMA token 过期或后端不可用 | 刷新 token |
| 前端页面打不开 | demo-chat 端口冲突 | 换 `--port 9090` |
| 中文显示乱码 | 浏览器编码问题 | 确认页面 UTF-8 编码 |

## 附录 A. 环境变量与配置参考

关键配置文件路径：`configs/maia/runtime/recognition.yaml`

```yaml
recognition:
  llm:
    model: "qwen/qwen3-4b-2507"         # LLM 模型名称
    base_url: "http://localhost:1234/v1" # LLM 服务地址
    api_key: "svcopilot local accessor"  # LLM API Key
    temperature: 0.1                      # 生成温度（低=更确定）
    max_tokens: 800                       # 最大输出 token
    retries: 2                            # 失败重试次数
  themis:
    alpha: 0.10              # embedding 通道权重
    delta: 0.10              # 判别阈值（第一名与第二名分差）
    min_intent_score: 0.50   # 最低可信意图分数
    build_index_on_init: false  # 启动时预构建索引（建议演示前改为 true）
```

## 附录 B. 给售前同学的三个核心信息

1. **MVP 不等于半成品，而是"核心闭环已验证"。** 记录检索 + 筛选 + 导出/趋势观察这条路径是稳的，聚焦演示这些。
2. **坦诚讲边界比吹牛有用。** 客户更关心"什么场景不适用"而不是"什么都能做"。上面第 5 节可以直接拿去当坦诚沟通的素材。
3. **这不是最终产品形态。** TASKS.md 和 REFACTORING.md 里有完整的重构计划（持久化、确认流程、审计等），可以展示"我们有清晰的演进路线图"。
